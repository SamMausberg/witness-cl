# Research position and strongest relevant controls

Primary sources checked 9 September 2026. These are antecedents and experimentally relevant controls, not a claim of an exhaustive search or a universal leaderboard. The repository's SQL fixture is not a native run of any external benchmark.

| Approach | What the primary source establishes | Boundary and consequence for Witness-CL |
|---|---|---|
| [Continual Learning Bench](https://arxiv.org/html/2606.05661v1), Asawa et al., 2026 | Six domains, stateful versus stateless gain, and the strongest aggregate result among evaluated systems from full-context ICL. | This is an empirical ranking on the reported configurations. Keep competent full history as a principal control; measure both reward and gain. Do not confuse this with Tencent's differently named context-learning CL-bench. |
| [AgentCL / MemProbe](https://arxiv.org/html/2606.02461v1), Shu et al., 2026 | Controlled compositional streams distinguish memory designs; MemProbe combines interactions, insights and skills with consolidation. | Related-task gains can coexist with degradation on naive or heldout tasks. A new relation admission is weaker evidence than fresh composition plus old-task evaluation. |
| [Voyager](https://arxiv.org/abs/2305.16291), Wang et al., 2023, and [Agent Workflow Memory](https://arxiv.org/abs/2409.07429), Wang et al., 2024 | Executable skill libraries with iterative execution feedback, and online workflow induction, respectively. | Programs, feedback-guided repair and skill reuse already have clear antecedents. Their domain-specific improvements do not certify our finite-budget SQL retention target. |
| [Dynamic Cheatsheet](https://arxiv.org/abs/2504.07952), Suzgun et al., 2025, and [ACE](https://arxiv.org/abs/2510.04618), Zhang et al., 2025/2026 | Persistent self-curated memory can include working code; ACE addresses loss of useful detail during iterative context rewriting. | A text baseline must be allowed SQL and exact observed conventions. Our old 6/8 summarizer is not a faithful implementation or a refutation of these approaches. |
| [Evo-Memory / ReMem](https://arxiv.org/abs/2511.20857), Wei et al., 2025/2026 | A streaming comparison of memory modules; ReMem interleaves reasoning, action and memory refinement. | Retrieval and consolidation both deserve ablations. Improvement on those streams does not imply no regressions on arbitrary future episodes. |
| [Memento 2](https://arxiv.org/html/2512.22716v2), Wang, 2025/2026, and [Memento-Skills](https://arxiv.org/abs/2603.18743), Zhou et al., 2026 | A reflected MDP formalization and stateful external skills, respectively. | The theory's local-consistency assumption already requires near-optimal LLM behavior near relevant cases; coverage and convergence assumptions do real work. It is not a finite-budget proof that arbitrary LLM reflection preserves every old answer. |
| [Titans](https://arxiv.org/abs/2501.00663), Behrouz et al., 2025, and [end-to-end TTT](https://arxiv.org/abs/2512.23675), Tandon et al., 2025 | Learned neural memory and test-time next-token adaptation provide alternatives to external textual storage. The latter meta-trains updateability. | They require appropriate model/training infrastructure. Their sequence-modeling evidence does not directly answer this stateful tool-use experiment; frozen-weight results cannot establish superiority over trained adaptive architectures. |
| [High Confidence Policy Improvement](https://proceedings.mlr.press/v37/thomas15.html), Thomas et al., 2015, and [confidence sequences](https://arxiv.org/abs/1810.08240), Howard et al., 2021 | Established routes to distributional policy comparisons and time-uniform inference under specified assumptions. | They supply statistical tools, not a representation learner. Frozen candidates, valid fresh samples, multiple-comparison accounting and the future-distribution assumption cannot be skipped. |

Query verification also has strong dedicated tools: [SQLSolver](https://www.cs.yale.edu/homes/piskac/papers/2024SIGMOD.pdf) proves supported SQL equivalences, and [VeriEQL](https://arxiv.org/abs/2403.03193) checks bounded equivalence with counterexamples. They are relevant future admission controls, not integrated results. A modeled equivalence is conditional on syntax, constraints and SQL semantics; preserving a source query cannot establish that it answers the intended question.

The incremental research opportunity is an auditable connection between own observations, executable contribution, later transfer, and fully charged deployment cost. An empty-relation check prevents the observed unused-CTE admission but remains easy to overinterpret: dependence is not correctness. The Lean finite-witness counterexample is a boundary on this inference, not a new general impossibility theorem for continual learning.

A serious benchmark comparison should start with the same competent backbone in full history, exact evidence with working SQL, retrieved episodes, a faithful evolving-text method, and executable memory. The current bounded development comparison uses only full history, exact evidence and repaired programs. If it succeeds, external methods require separately implemented and qualified controls before a superiority claim.

The next mechanism proposal in the paper is **delayed corroboration**: keep a candidate provisional until a future, independently encountered episode corroborates its source computation with a meaningful changed binding, then test a new outer computation separately. This is a hypothesis. The cost may exceed any later savings, and semantic restrictions may remove useful candidates. Neither the literature nor the current code resolves that tradeoff.

The paper also proposes a distinct inference experiment: expose database observation freshness, then separately require the answer action to reference a numeric result executed in the current episode and have the host emit it. This tests stale scalar replay under the same interface for every arm. It is not implemented; extra queries may erase its value, and a current query can still be semantically wrong or return a copied constant.
