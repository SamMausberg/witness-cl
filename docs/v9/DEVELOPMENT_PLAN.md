# v0.9 development: cross the competence threshold and exercise reuse

This is a new development phase authorized by the user's September 9 request to address the v8 critique and work toward a fix. All v8 frozen sources and results remain unchanged. No additional Lean theorem is a goal of this phase.

The first experiment compares the unchanged v8 solver instruction with a clearer shared evidence-acquisition instruction on the same new development seed 92000, initially with stateless memory. Both use the existing Qwen3-4B Q8_0 weights, greedy non-thinking decoding, the same JSON action schema, 384 output tokens, eight SELECT attempts and ten action calls. The new prompt explains how to acquire catalog meaning, forbids guessing from opaque column positions, and spells out that false correctness feedback means failure. It supplies no gold answer or domain query. Catalog reads execute and count. Source and request settings are hashed before each run.

If that solver remains below 7/8 warm accuracy, bounded follow-ups may test a declared sampling/reasoning setting or the Qwen3.5-9B Q8_0 model (Unsloth quantization of Qwen weights). Model download, loading and hashes are reported separately. Every actual diagnostic, including failed variants, is retained and reported. No result from these adaptively chosen development variants is confirmatory evidence or a causal ablation of every prompt sentence.

A competent candidate must then qualify with the actual full-history and evolving-insight controls, and with the proposed memory arm. The target is at least 7/8 warm accuracy, plus nonzero correct answers and evidence of documentation use, before a full transfer run. Empty memory has the same initial message representation across methods. Existing valid documentation in history must remain reusable without forced re-query. No direct SQL capabilities are removed from controls.

The mechanism test requires actual new relation proposals from an agent's own correct executed queries, charged reconstruction, subsequent changed bindings or a novel outer expression, fresh correct results, and a diagnostic establishing dependence on the learned relation. Admissions alone are not successes. The current guard costs at least one extra SELECT per use; a direct history solver can already reach a one-SELECT floor. Report interaction, model tokens and elapsed time separately and do not silently replace the original interaction-saving claim with a token-saving claim.

Development seeds are 92000–92003. Seed 92000 is for adaptation; 92001–92003 are available for separately frozen development replication after a candidate is chosen. No prospective heldout seed (93000+) or v8 heldout fixture may be used in this phase. Stop on unknown model usage, a changed source during a run, an unidentified server, or its declared resource ceiling. Existing run directories cannot be overwritten.

This phase permits at most 45 minutes of measured model-experiment execution in aggregate (not a per-retry allowance), 4,000,000 total model tokens, and 1,600 generation calls. Setup/download is separately recorded. Each call retains its prompt, effective decoding configuration, answer/reasoning fields, finish reason and complete token usage. These ceilings bound development; they do not promise a powered study. Before any broader comparison, update the concrete run plan and freeze it independently. Keep the model server authenticated, loopback-only, without built-in tools; stop owned servers and remove temporary keys afterward.
