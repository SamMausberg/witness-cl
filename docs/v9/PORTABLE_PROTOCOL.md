# Final bounded development attempt with compatible schema transport

This is the final model-run configuration of this development phase. All earlier diagnostic and failed/interrupted attempts remain separate, immutable evidence. Their resource use, including conservative reservations for missing usage, counts toward the same original development budget. No more task-model attempts follow this one in this phase.

## Why a further transport correction is necessary

The first stream failed because the native schema grammar could not expand a 4096-character string bound. The JSON-only follow-up retained actual host validation, but its first two text-memory updates were rejected: one final-content field contained unfinished reasoning after the forced reasoning boundary; another used a top-level array. The fragment learner also produced an invalid wrapper and a fenced response. We intentionally stopped that invocation rather than treating its empty evolving memory as a strong trained baseline. Its last request timed out during owned-server shutdown, and missing usage remains explicitly unknown.

The selected client returns to detailed schema-constrained generation. A small, separately frozen adapter removes only string maxLength values greater than 2000 from the **wire schema**. The host retains and validates the original schema and existing per-string/active-memory bounds. JSON object shape, required fields, arrays, scalar types and smaller bounds remain in the wire schema. Each call records both schemas, its policy and its actual decoding. It never repairs a response, removes reasoning from a response, edits SQL, retries a model call, or supplies a missing abstraction.

The native forced reasoning cutoff is disabled (`--reasoning-budget -1`). The 2048-token solving allowance still bounds total generated reasoning plus final output. All memory reflection and proposal calls use nonthinking decoding with a common 4096-token allowance; solving uses thinking decoding. This shared phase rule applies identically to every memory method. It prevents verbose summarization from exhausting the development runtime and is part of the tested algorithm configuration, not an unreported decoding fallback. All decoding fields except the phase's thinking Boolean remain temperature 0.6, top_p 0.95, top_k 20, min_p 0, presence_penalty 1.5 and seed 42.
