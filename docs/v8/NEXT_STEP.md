# Next decision after the failed abstraction pilot

The current experiment does not establish discovered executable reuse, superiority over competent full-history/evolving-memory baselines, or retention of useful prior behavior. Scaling the same frozen configuration would increase the sample size of a competence failure. The finished 288-episode record is preserved.

## Repair and qualify the shared solver first

Use a new versioned development protocol with disjoint seeds. Freeze one shared solver interface and model setting across every memory arm before comparing them. Candidate repairs are explicit handling of unknown schema meaning, clear failure/success feedback labels, and model settings that permit enough reasoning to interpret the catalog. These are hypotheses, not verified improvements. A stronger model is another candidate; it must solve the same task from the same permitted evidence, and all its inference must count.

A catalog query is legal for every method. A repair must not give executable memory free catalog facts, a hand-coded target program or an extra uncharged exploration step. Full-history and insight methods must retain the ability to produce direct compositional SQL. If a shared acquisition policy forces queries a competent history baseline would otherwise avoid, report that policy as a restriction rather than describing the baseline as strong.

Before a transfer comparison, require at least 6/8 warm answers for both mandatory controls and at least 6/8 on the proposed learner's fresh old panel. Preserve absolute scores and constant-count items. Also demonstrate that failure feedback is interpreted correctly and the solver acquires the documented units, profile-currentness, joins and missing-value rules. Transport-only output checks are insufficient: the two pre-pilot transport tests did not establish these abilities.

## Test whether SELECT saving is attainable

A full-history solver can express the target in one direct SELECT once it knows the schema conventions. Checked fragment reuse needs a guard and an execution, plus amortized synthesis checks. The current architecture therefore has no automatic SELECT advantage over a competent direct solver. Measure the baseline's actual exploration cost before making the saving hypothesis primary.

An executable library could reduce prompt tokens, generated SQL tokens or reasoning time without reducing database interaction. Report those as separate outcomes if observed; do not silently replace the requested interaction outcome. If direct SQL is already at its one-query floor, a different task family with genuine sequential observation dependencies or a different explicit interaction hypothesis is necessary. Do not manufacture an advantage by disabling joins, history or composition for controls.

## Require an actual discovery-to-transfer trace

On its own ordinary experience, the agent must propose a relation, reconstruct a witnessed answer through a charged execution, and subsequently solve fresh questions by changing bindings and a new outer computation. Merely generating a new SQL string or a passing scalar reconstruction is not enough.

Record the source queries, admitted program, arguments, expanded SQL and result. Verify that the final answer depends on the learned relation. Remove or replace the relevant fragment in a matched diagnostic to distinguish learned executable reuse from a constant answer, an unused CTE or information already supplied as textual memory. Diagnostics have their own counted cost and must not consume primary heldout tasks for tuning.

## Only then plan confirmation

Freeze the source, prompts, actual baseline implementations, model, all costs, disjoint heldout seeds, analysis and multiplicity correction before any heldout model run. A split label alone does not guarantee fresh data seeds in the present generator. Include reusable, nonreusable and visible near-match conditions, reporting all outcomes rather than selecting a favorable condition.

The declared target is simultaneous evidence of at least 25% SELECT saving against both full-history and evolving insights, no more than two percentage points of accuracy loss against either, and no more than two points of old-task regression. Streams, not correlated questions, are replication units. A single pilot cannot support these margins. Model and resource feasibility must be demonstrated before choosing a powered sample size; the approximate 326/82-stream illustrations in the protocol are not a run plan or an observed power calculation.

No new model run, heldout run or automation is created by this document. The actual v8 model server was stopped after the completed development pilot.
