# What the refinement actually resolves

The previous three design questions now have explicit implementations and tests,
not just future-work paragraphs. Their unrestricted versions are not declared solved.

| Question | Constructive answer | Executed evidence | Remaining boundary / kill result |
|---|---|---|---|
| Useful representations without hidden task IDs | Schema-derived typed relational plans; strict model-proposal parser; honest replay when the class grows | SQLite/interpreter/cube parity; fresh-database transfer; growth regression | Multiplication outside the shipped grammar still fails; general natural-language skill discovery is not demonstrated |
| Admission within realistic budgets | Frozen local residuals; identical zero-skipping e-process; live randomized control-variate estimator; multiscale/predictable paired test | Exact identity and unbiasedness tests; power study; integrated one-outcome agent | Diffuse small gains still need many samples; gated data can arrive too slowly; audited system loses reward to audition cost |
| Retention under hidden recurrence | Immutable archives; archive-weighted recovery; optional fixed-share bandit router | Return-to-old-rule tests, old-output invariants, noisy/rapid-switch stress tests | Selection errors remain; noise corrupts hard elimination; tracking is a separate fixed-archive control |
| Online parameter learning without erasing protected behavior | Frozen-feature projected residual | Online SGD and drift/capacity measurements | Full-rank protection blocks all learning; does not preserve arbitrary old LLM behavior |
| Efficient execution | Shared predicate cube; packed evidence and consensus CUDA drafts | Python/SQLite/C++ checks; CPU factorization timings | No GPU compilation, timing, throughput, or LLM end-to-end speedup claim |

## Claim hierarchy

**Established by executed tests:** the scoped mechanics, reported CPU simulation
results, exact Fraction estimator identities, and C++ oracle self-tests.

**Established mathematically conditional on stated assumptions:** version-space
replay identity, weighted elimination bound, local noninterference, exact fixed-
feature protected span, and the finite-class cube identity. Statistical and
tracking derivations apply standard established methods under their explicit
sampling/feedback assumptions. Handwritten proofs still need independent review.

**Attempted formalization:** 29 Lean declarations, no proof placeholders. The
local `lake build` did not run because `lake` is absent. Attempts to obtain the
compiler failed. No kernel-checked theorem count is claimed.

**Hypothesis, not result:** better real-agent continual reward/cost/retention than
matched raw ICL, ACE/MemProbe, or EvoTest/TTHE. No native CL-Bench/AgentCL run and no
model-service call was executed. The neural, soft-router, and multistep-coupling
branches are not all integrated into one general LLM agent.

## Narrow publishable claim to pursue

An evidence-preserving typed skill compiler, explicit recurrence recovery, and
support-local admission can close concrete failure modes of deployment-time
learning while exposing the cost of statistical conservatism. The combination's
novelty has not been established by this search. Program synthesis, orthogonal
updates, fixed-share tracking, and sequential testing must receive credit.

## Prespecified next falsification

Start with native database and codebase streams, then the other CL-Bench domains;
retain raw ICL as a primary competitor and a full-information symbolic solver
only as a mechanism control. Use fresh schema names, unseen plan compositions,
real NULL/key/cardinality changes, correlated errors, hidden recurrence, and
unsupported operators. Every arm gets the same task observations and interaction
budget. Charge proposal calls, screens, forks, rejected candidates, updates, logs,
and retrieval. Freeze parser/model/tool revisions and random seeds.

The broad superiority claim is killed if gains vanish with matched budgets,
stronger ICL, or unseen compositions; a subgroup retention loss exceeds the
prespecified margin; or guarded opportunities arrive too slowly to repay auditing.
A kernel claim is killed if full replay/transfer/launch cost exceeds the saved
work. Independent validation is required before presenting any result as a public
benchmark win. Current negative results are part of the main paper, not exclusions.
