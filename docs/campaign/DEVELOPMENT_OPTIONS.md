# Prospective development options after candidate 2

This note specifies options for a later candidate if the completed candidate-2
development study misses its mechanism or cost gates. It authorizes no change to
the running qualification, its four assigned development streams, their copied
sources, or their stopping rules. Finish and audit those schedules before choosing
an option. Preserve unsuccessful candidates and their measured costs.

The motivation is limited evidence. The
[static capacity audit](../../artifacts/campaign/static-capacity-audit-v1.json)
fed saved candidate-1 cold traces into memory only as software fixtures. Repeated
catalog text occupied 58–62% of the compact payload; scoped deduplication would
have retained all recorded SQL within the same byte limit. It measured no
counterfactual model accuracy. The
[candidate-2 source diagnostic](../../artifacts/campaign/static-source-compatibility-dense-v2.json)
found that all 64 correct cold sources lift, but none of 16 planned source pairs
matches the current exact template identity. Fifteen unchanged sources reproduce
the later answer when that identity gate is bypassed diagnostically. Offline
reference-authored compositions work on 31/32 fresh probes. These are neither
actual admissions nor evidence of stateful model reuse. Actual development may
stabilize SQL through visible prior experience and must be evaluated directly.

**Option 1: deduplicate repeated observed documentation.** Keep the existing
allowlist for direct catalog projections and exact text-only observations. Give
each such record an observation identity containing the public schema hash, SQL,
parameters, returned columns and exact text rows. Exclude the current task's
question from that identity. Retain the latest complete observation record, while
the full archive preserves every original query, question, result and charge.

The query and parameters remain in the identity: identical description strings
returned by differently scoped partial queries must not be conflated. A changed
catalog or schema creates a different observation. Do not discard older distinct
conventions merely because a migration occurred. Keep the 65,536-byte active cap,
existing eviction order and complete provenance accounting. Apply the same rule
to compact SQL, delayed, immediate and view-text arms. Full history remains its
complete recorded conversation; ACE retains its official evolving playbook.
This changes storage, not access to evidence, and requires its own cost result.

**Option 2: narrowly normalize syntax for identity comparison.** A first bounded
candidate could canonicalize unqualified `JOIN` and `INNER JOIN` identically where
the parsed join has no outer side or special method. Existing parsing already
handles many spacing, quoting and case differences. Keep the original source
view, reconstruction wrapper, binding values and receipt hashes immutable; a
versioned comparison fingerprint must never substitute rewritten SQL for the
source actually executed and witnessed.

Alias normalization is a separate, harder extension. It would need a
scope-aware, capture-avoiding renaming with consistent updates to derived-column
references, CTE names, lineage and typed binding anchors. Ambiguity must abstain.
Do not strip aliases textually or equate columns by spelling alone. Test nested
scopes, shadowed names, correlated subqueries and output-column references before
freezing any such extension. Successful finite-data checks do not prove the
normalizer correct on every database.

Do not include algebraic or NULL-sensitive rewrites in this option. `SUM(x)` and
`COALESCE(SUM(x),0)` differ on empty input. Moving division across an aggregate,
changing arithmetic association, removing CASE expressions, relocating filters
across joins, or changing duplicate handling can alter SQLite results. Two cold
pairs differed only in the outer NULL default; that observation does not license
erasing the difference. Every accepted lexical match would still require the
existing charged reconstruction and empty-relation checks.

**Option 3: corroborate the unchanged prior source without demanding that the
later solver write the same template.** This is a different admission policy,
not a claim of SQL equivalence. After a later direct QUERY receives correct
current feedback, choose at most one compatible provisional source using a
prespecified deterministic rule over public schema/catalog scope, question text
and the recorded direct SQL. Commit its identity before running any diagnostic
check. Do not rank candidates by agreement with the answer or try alternatives
after a failed check.

Map only already exposed source holes to later observed bindings. Require a
unique mapping with identical scalar types and resolved predicate anchors,
including scope, relation role, physical column and operator where applicable.
Physical-column equality alone does not distinguish self-join roles. Preserve all
non-hole constants, source SQL, joins and the original scalar wrapper. Ambiguous,
missing or incompatible mappings abstain. A literal fixed inside a JOIN and not
exposed as a source hole remains fixed; this policy cannot silently turn it into
a parameter. It cannot invent a fresh relation or repair a source expression.

Run the original reconstruction with those mapped bindings on the later fresh
database, compare with its independently obtained direct answer, and run the
empty-relation intervention. Both checks must fit the existing SELECT allowance;
no retries, extra candidate search or new model calls are allowed. Require a
later episode, changed binding and changed numeric output. Commit immutable
receipts and make the corroborated entry selectable only from the following
episode. Never route candidates using evaluator family IDs, seed conventions,
reference SQL, expected answers or future tasks.

The resulting claim is observational corroboration on two witnessed episodes.
Coincidental equality, unobserved NULL cases, wrong multiplicity and future drift
can still defeat the relation. Emptying a relation establishes dependence on its
rows, not the necessity or meaning of a computed column. Keep public scope
matching, future USE/COMPOSE traces, computed-column lineage, fixed-program
interventions and actual agent deletion reruns. Changing candidate selection must
not broaden those proofs or imply universal semantic preservation.

**Controls and contracts for any new candidate.** Preserve the current-query host
answer receipt, closed relational-program continuation, unchanged source payload,
delayed publication, frozen panels and complete token/SELECT accounting. Every
attempt, rejected check, rationale, retained byte and unknown usage remains
visible in the ledger. Keep the common paid current catalog and common solver
interface. The same-extra-direct-queries assay must use the revised acquisition
rule in its donor and expose the identical checks, bindings, results and feedback
to every fork, including rejected attempts. Charge the complete donor prefix to
each logical fork and report shared physical cost separately. Run view-text and
immediate controls with the same extraction/storage policy. If deduplication and
admission change together, the main result concerns that combined candidate;
component attribution needs separately prespecified ablations.
Native adapters must retain their pre-terminal checks and post-feedback commit
boundary; this note does not permit SQL after a native ANSWER.

**Fresh evaluation requirement.** Choose one implementation and freeze its code,
limits, normalization or mapping version, selection rule and seed registry before
new calls. A possible next unused allocation is qualification reuse
100300–100301, qualification drift 100302–100303, and four development streams
101200–101203. These are proposals, not reservations: first check all campaign,
assay and native run inventories for overlap, then commit the registry. If any
are already observed, allocate a wholly fresh block. Each additional candidate
needs its own fresh allocation; never reuse a failed stream as a replacement.

Freeze both qualification schedules before either runs. Retain 32 cold episodes
per seed, 7/8 initial and 6/8 in each remaining cell, and complete every assigned
episode. Then complete all four newly frozen development streams. Require at
least five actual audited delayed mechanism events over at least three streams
before sizing; static diagnostics contribute zero events. A selected candidate
requires a fresh, complete 32-stream sizing study and a separately frozen,
disjoint confirmation sized by the existing power rule. Do not pool outcomes
across candidates or borrow their apparent gains.

The five positive endpoints remain unchanged: future accuracy superiority over
both full history and faithful ACE; total token ratio below 0.80 against each;
and old-panel noninferiority within 0.02, using the prespecified stream-level
tests. Keep the stable/drift, nonreuse, evidence-matched and native evaluations
and their stated scopes. A negative completed result remains reportable; it
cannot be converted into success by weaker thresholds or altered margins.
